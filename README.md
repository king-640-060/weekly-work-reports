# 个人工作周报

个人工作周报管理与历史归档。每周按项目整理真实工作成果和下周计划，同时保存 Markdown 阅读版与可复制到邮箱正文的 HTML 邮件版，便于长期检索、复盘与持续更新。

## 命名与固定格式

- 文件名：`YYYY-MM-DD_YYYY-MM-DD.md` 和同名 `.html`，分别表示统计周期的开始、结束日期。
- 归档目录：`reports/YYYY/`，以开始日期所属年份归档；跨年周也遵循此规则。
- 标题：`工作周报（YYYY.MM.DD—YYYY.MM.DD）`。
- 正文标题：`一、个人项目概述`。
- 表格固定为「项目名称 / 本周完成工作 / 下周计划」三列，每个项目占一行，编号事项在同一单元格中分段。
- 当前历史周报采用周六至周五的统计周期；新一期以用户明确的日期为准，不按运行当天自动推断。

## HTML 邮件表格使用方法

1. 从仓库下载对应 `.html` 文件，或克隆仓库后在本地找到该文件。GitHub 的文件页显示源代码，不是邮件预览。
2. 用浏览器直接打开 HTML 文件。
3. 在页面正文中按 `⌘A` / `Ctrl+A` 全选，再按 `⌘C` / `Ctrl+C` 复制；也可用鼠标仅选中表格。
4. 在邮箱的**富文本编辑模式**中粘贴，选择「保留源格式」（如有）。不要使用「粘贴为纯文本」。
5. 发送前检查表格边框、列宽、编号分段和文字是否完整。

模板采用真正的 HTML `table`、内联 CSS 和兼容的表格属性。所有单元格带 `1px` 实线边框，列宽约为 **18% / 53% / 29%**，文字左对齐、顶部对齐，正文使用 14px 中文办公字体。每个编号事项使用单独的 `p` 段落，同一事项自然换行，不按短句硬拆分。

不同邮箱可能会清理部分样式，粘贴后以实际邮件预览为准。浏览器直接打开 HTML 即可使用，不依赖脚本、外部字体或在线资源。

## 每周更新流程

详细规则见 [WORKFLOW.md](WORKFLOW.md)。

1. 提供统计周期和本周实际工作，按自然语言描述即可。
2. AI 按项目分类，整理成果、真实进度与承接本周进度的下周计划，输出草稿。
3. 用户确认或修改，并检查拟公开内容。
4. 依据 [Markdown 模板](templates/weekly-report.md) 和 [HTML 模板](templates/weekly-report.html) 生成内容一致的两个版本。
5. 保存到对应年份目录，更新下方历史索引。
6. 检查 HTML 和链接后，提交并推送到 `main`。

后续交给 ChatGPT / Codex 时，可直接使用这段话，并附上仓库内容或提供仓库访问能力：

> 请先阅读 weekly-work-reports 仓库中的 WORKFLOW.md 和两个模板。整理 YYYY.MM.DD—YYYY.MM.DD 的工作周报，以下是本周实际工作及下周安排：……。先输出草稿，等我确认后再生成 Markdown 与 HTML、更新索引、提交并推送。不得编造进展或覆盖其他周报。

手动更新可先克隆仓库，再复制两个模板，替换日期及内容，更新索引后提交：

```bash
gh repo clone king-640-060/weekly-work-reports
cd weekly-work-reports
# 完成并核对新一期 .md、.html 和 README.md 后执行：
git add reports/ README.md
git commit -m "docs: 新增 YYYY-MM-DD 至 YYYY-MM-DD 工作周报"
git push origin main
```

本仓库为公开仓库。发布前请去除内部敏感业务数据、未公开商业机密和个人隐私；无需记录的原始材料请保留在仓库外。
